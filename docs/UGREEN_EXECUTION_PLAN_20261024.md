## 제품 흐름과 기능 범위
1. 사용자가 검사할 승인된 프로젝트 폴더 + 필수 산출물 목록(또는 접근 허용된 요구문서)을 지정한다.
2. 실제 지원되는 UGOS CLI·등록 Expert Agent만 사용해 허용 파일/문서 검색·조회한다.
3. 필수 자료 누락 검사(feature/missing-files): 명시된 기준에 대한 증거·누락 사유를 반환한다. 기준 미제공이면 추측하지 않는다.
4. 버전 충돌 후보 검사(feature/version-conflicts): 지원되는 파일명·메타데이터·문서 정보만 사용한다. 해시/버전 이력 비교는 키트가 실제 지원할 때만 사용한다.
5. 개인정보/외부반출 위험 게이트(feature/privacy): 지원 기능과 권한 내에서 검사. 내용 검사 불가 시 'Not checked'로 표기하고 안전 판정 금지.
6. 증거 경로·차단 사유·다음 조치 보고. 자동 삭제·이동·덮어쓰기·외부 업로드 금지. 위험 변경은 사용자 명시 승인.

차별화 가설: 범용 중복파일 청소가 아니라 '납품 요건에 대한 증거 기반 Go/No-Go 판단'. 심사 결과 및 현재 Uliya 호환성은 검증 전.

## 필수 검증 시나리오
- Core 1: 완비된 필수목록 + 충돌 증거 없음 -> 검사 가능 범위에 한해 Ready. 검사되지 않은 필수 항목이 있으면 Needs review.
- Core 2: 명시 산출물 누락·여러 최신본 후보 -> Blocked/Needs review, 파일 근거와 조치 필요.
- Edge: 권한 거절·미지원 CLI·빈 결과 -> Unsupported/Not checked를 명시, 환각 대체/위험 행위 0건.
- 반복 호출은 원본 데이터 불변, 동일 근거라면 일관된 결과.
- 예선 ZIP 문서 구조 검사 = 실제 NAS 작동 증명이 아님.

## 공식 제출 계약
- 영어 PDF: 공식 질문 10개, 총 500단어 이하, 파일 1MB 이하.
- ZIP: SKILL.md 필수, 직접 링크된 references/의 Markdown만 선택. 별도 scripts / manifest / binaries / executables 금지.
- ZIP 압축/해제 크기 각각 <=10MB, 파일당 <=1MB, 100개 이하. frontmatter name 소문자-하이픈 2~64자, description <=1024자.
- 제3자 출처/라이선스, AI 도구와 주요 용도, 외부 서비스/데이터 흐름 공개.
- 공식 Kit 안내의 README 추천 vs Round 1 Rules의 허용 파일 범위 충돌 시 Rules 우선. README는 개발 저장소에는 보관 가능, 제출 ZIP 제외.
- Round 1 별도 코드 링크·영상·NAS 런타임 증거 불필요. 참가자당 프로젝트 1개. 이전 개발 Skill 핵심 제출 재활용 금지.
