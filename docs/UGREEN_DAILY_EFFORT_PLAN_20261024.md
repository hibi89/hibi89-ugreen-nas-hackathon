# ProjectReady NAS — 일별 보수적 작업시간·완료기준 및 일정 위험
**작성 기준**: 2026-10-24 KST. **담당**: UGREEN 단독 총괄 겸 직접 개발자. 현재 상태: UGR-001 공식 Kit 내부 CLI 접근 BLOCKED, 공개 문서 역량표만 존재. 날짜는 **KST**. 이 시간들은 확정된 실제 기록이나 보장된 소요시간이 아니라, 실제 일을 잘라 실행하기 위한 **상한 시간 예산**이다.

> **최우선 결론:** 기존 11/10 '조기 제출 목표'를 지금 시점에서 안전하게 달성 가능하다고 판정할 수 없다. 공식 아카이브/CLI가 아직 막혔고 세 해커톤이 같은 사람의 일정에 영향을 준다. 11/10은 **조건부 조기 시도**, 11/14는 **실질적 예비 제출 시점**, 11/16 16:45 KST는 **절대 공식 마감**이다. 조기 날짜를 임의로 공식 마감으로 바꾸지 않는다. 11/14 역시 SDK 차단이 계속되면 보장되지 않는다.

## 시간 산정 규칙 — 기존 '4시간이 8~20시간' 오류 방지
- **계획시간** = 해당 날짜에 해낼 **작은 단일 묶음**에 배정하는 보수적 실작업 예산. 예전 낙관적 코딩 예상의 약 **2배**를 시작값으로 사용했다. 검증되지 않은 CLI/SDK 조사처럼 변동성이 큰 일은 계획시간만으로 끝난다고 주장하지 않는다.
- **예비시간** = 발견된 오류·검수·환경 차이에 쓸 **추가 확보 가능 시간**으로, 계획시간에 이미 포함된 것이 아니다. 사용하지 않으면 소모하지 않는다. 각 날 **최대=계획+예비**; 실제 소요가 상한을 넘으면 '당일 완료'를 주장하지 않고 BLOCKED/이월, 작업 분해, 일정 재산정.
- **소요시간은 능동 작업시간**(GitHub 조사, 코드 작성, 테스트, 수정, PDF 검토)이며, UGREEN 커뮤니티 회신·외부 SDK 제공 승인 같은 **통제 불가능한 대기시간은 제외**한다. 대기시간은 전체 일정을 늦출 수 있다.
- **본 표는 UGREEN 1개 대회의 시간만이다.** KIC·PayPal 작업시간을 여기에 더하지 않았다. 세 대회 합산 하루 8~12시간을 전제로 하지 않는다. 전체 총괄이 타 대회별 시간표와 합산해 하루 현실적인 가용시간을 별도 검수해야 한다.
- 문제 원인이 밝혀지지 않고 동일 방법이 1~2회 실패하면 멈춘다. 한 문제에 60~90분 이상 진척이 없으면 다른 합법적 방법 또는 공식 지원 경로로 변경하고 차단 기록. **확실하지 않은 일을 '몇 시간 안에 완성'이라고 약속하지 않는다.**
- 첫 실제 개발 이틀 후 추정 대비 실제 작업시간을 기록하고 재추정. 실제가 계획보다 **1.5배 초과**면 다음 날짜 배당을 즉시 수정하고 상위 총괄에 일정 위험 공유. 같은 유형 두 번 2배 이상 초과 시 이후 작업 예상치를 재산정할 때 기존 낙관적 추정치를 사용하지 않는다.
- 사용자 명령 `ㄱ` 또는 `[유그 해커톤 깃헙 레포지토리 확인하고 작업하셈]`을 받으면 현재 실작업을 실행한다. GitHub의 시간표 작성만으로 그날 일을 수행했다고 표시하지 않는다. 상한시간이 찼을 때 자동 백그라운드 실행하거나 다음 날 완료를 보장하지 않는다.

## 3개 해커톤과의 충돌 회피
- **KIC** 내부 조기 제출 11/10 및 공식 마감 **11/12 10:00 KST**. UGREEN은 11/10 최대 1.5시간, 11/12 최대 비상 0.5시간이다.
- **PayPal** 내부 조기 제출 11/11 및 공식 마감 **11/13 05:00 KST**. UGREEN은 11/11 최대 1시간, 11/13 최대 비상 0.5시간이다.
- 다른 두 대회가 지연되면 먼저 사용자와 전체 총괄이 통합 일정의 하루 총액을 확인한다. **UGREEN 일일 예비시간은 다른 대회의 필수 제출 시간을 뺏어 쓰라는 허가가 아니다.** 자원이 실제로 없으면 UGREEN 작업을 이월하고 위험을 기록한다.

## 강제 기술 게이트·판정 기준
1. **10/27 G1/G2 게이트 (P0):** 실제 다운로드한 공식 Kit/허용 CLI·등록 Expert Agent와 권한/입출력 증거가 없으면 `SDK_BLOCKED`; SDK 호출을 창작하거나 미지원 기능을 구현 완료로 표시하지 않는다. 지체 없는 제3의 합법적 공식 근거 또는 지원 채널로 전환. 주요 기능 축소/전송·유료 사용 변경은 사용자가 결정해야 한다.
2. **10/31 데이터 검증:** 누락과 불확실·모호를 구분하는 최소 테스트가 아직 재현되지 않으면 뒤의 품질 보장을 내세우지 않는다. 실패 이력을 기록하고 11/01 이후 시간을 조정한다.
3. **11/06 실제 패키지 적격성:** `SKILL.md`와 직접 연결된 `references/*.md` 등 공식 Round 1 규격과 검증 가능한 CLI 근거. 공식 아카이브 불가로 검증이 안 되면 **실 NAS/공식 툴 PASS로 표현 금지**.
4. **11/09 출시 결정:** 필수 컴포넌트와 PDF/ZIP 후보 모두 검사되어야만 11/10 최종 조기 제출을 시도한다. 미달하면 `NO-GO` 표시, 11/14 대체 시나리오를 사용자·상위 총괄에 보고한다. 날짜가 다가온다고 기능을 무단 포기하거나 가짜 CLI를 넣지 않는다.
5. **11/14 비상 게이트:** 가능하면 실제 영수증을 확보. 미제출이라면 11/16 16:45 이전 대체 가능한 공식 규격 산출물과 제출 위험을 즉시 사용자에게 명시한다. **11/16 당일 개발·전면 재구성 금지**.

| 필드 | 의미 |
|---|---|
| 날짜/작업 ID | 해당 일자·작업 내용/코드 범위 |
| 계획/예비/실측(시간) | 추정과 실제를 분리; **미측정은 '미측정'** |

| 테스트/원격 SHA | CLI·합성·NAS·PDF·ZIP 각각 PASS/FAIL/NOT_RUN 구분 |
| 이월·재추정 | 다음 작업으로 넘어갈 때 추가 소요 추정, 다른 대회와 충돌 여부 |
