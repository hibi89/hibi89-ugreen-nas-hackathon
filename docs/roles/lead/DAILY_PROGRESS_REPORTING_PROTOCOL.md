# UGREEN — 작업 종료마다 100% 기준 진행률·잔여시간 공시 규약
유효일: **2026-10-24 KST**. 소유자: UGREEN 총괄 겸 개발·테스트 담당, `lead/ugreen`. 사용자의 명시적인 상시 지시: **각 작업이 끝날 때마다 그날의 전체 작업량을 100%로 놓고 진행률과 남은 작업시간을 반드시 보고한다.**

## 1. 시작 전
1. [UGREEN_DAILY_EFFORT_PLAN_20261024.md](../../UGREEN_DAILY_EFFORT_PLAN_20261024.md)에서 **오늘(KST)** 계획/별도 예비 시간과 완료 기준을 확인. 일정 날짜보다 먼저 일을 진행한 경우 실제 실행일을 기록하고 예정일을 별도로 적는다.
2. 해당 **하루 작업만** 검증 가능한 2~6개 세부 결과물로 분할하고 각 항목 `weight_percent`를 미리 배정해 **정확히 100%**. 예상 난이도와 안전 중요도를 반영하되 중요한 불확실/필수 게이트 비중을 지나치게 낮추지 않는다.
3. 필수 게이트가 차단돼 있다면 세부 목표가 일부 끝나도 **전체 SDK/NAS/제출 성공과 구별**한다. 최종 제출 성공률 같은 임의 수치는 만들지 않는다.

## 2. 종료 때마다 (같은 커밋에서)
1. 현재 날짜의 `DAILY_PROGRESS.json` 각 항목을 `DONE`, `IN_PROGRESS`, `BLOCKED`, `NOT_STARTED`, `SKIPPED` 중 하나로 기록. **증거가 있는 DONE만** 완료율에 포함하고 나머지는 0%로 계산. 일부 완료는 작은 항목으로 나눠 별도 증거를 남긴다. 100%라도 공식 제출 게이트가 BLOCKED면 '전날 업무 항목 100%'와 '대회 미제출'을 구분.
2. **완료율 = Σ(DONE 가중치), 미완료율 = 100 - 완료율**. 코드 검증기를 통해 합계 100 및 일치 여부 검증한다. 반올림한 직감 퍼센트, 코드 라인수/테스트 수로 진행률을 추정하지 않는다.
3. **남은 기준 작업 배당시간 = 그날 계획시간 × 미완료율/100, 소수 첫째 자리 반올림**. 이 값은 **작업 배당 비례 계산**이지 실제 완료까지 걸릴 시간은 아님. 별도 예비시간은 다른 칸에 유지한다. 실사용 미측정이면 '예비 1.5h 미사용'이라고 거짓 표시하지 않는다.
4. 실제 작업 소요 측정이 가능한 경우만 `actual_active_hours` 기재; 측정되지 않았으면 null/미측정. 다음 작업 재예측 및 1.5배 초과 시 보고. 외부 답변 대기·SDK 불확실 시간은 **'실제 완료 ETA 산정 불가'**라고 명시하여 0.4h 같은 예산 수치를 완료 약속으로 쓰지 않는다.
5. `DAILY_PROGRESS.md`, `DAILY_PROGRESS.json`, `LEAD_ACTIVE_WORK.md`, `STATUS.md`, `HANDOFF.md`, `TO_HACKATHON_LEAD.md`, `WORK_TIME_LOG.md`와 필요시 날짜별 시간표 수정. **현재 스냅샷 1개 + 과거 날짜 기록 보존**.
6. GitHub에 커밋→푸시→**원격 HEAD/SHA·CI 테스트 확인**. 사용자 최종 메시지는 반드시 `오늘 XX% / 남은 YY% / 남은 기준작업 Xh + 예비 Yh / 실제 완료 ETA(값 또는 산정불가)`와 미완료 사유를 포함한다. 문서 정책 변경만으로 제품 진행률을 올리지 않는다.

## 3. 주의 및 교차 보고
- **'작업 종료'는 작업 요청 단위마다** (동일 날짜 다회 호출이면 누적 실측/항목 상태), **'하루 100%'는 해당 날짜 작업계획을 기준**으로 유지. 하루가 바뀌면 당일 새 100% 계획을 작성하되 전날 미완료는 다음 날에 **이월**되었음을 명시한다.
- 원래 작업 범위 자체가 변경되면 이유·승인·이전 분모 및 새 분모를 함께 기록하여 진행률 조작을 방지한다. 미착수 날짜는 진행 0%로 표기하며 임의 완료 취급 금지.
- 본선 진출 시도 [조건부 별도 계획](../../UGREEN_FINALIST_DAILY_PLAN_20261024.md), 공식 선정 전 ACTIVE 아님. 매 작업 100% 비교 규칙은 본선에서도 동일하다.
- KIC/PayPal 일정과 혼동하지 않는다. 상위 총괄은 `TO_HACKATHON_LEAD.md`의 최신 비율 및 직접 [DAILY_PROGRESS.md](DAILY_PROGRESS.md)에서 현황 확인. 통합 상황실이 임의로 미확인 데이터를 100%로 변경하지 않는다.


## 2026-10-24 사용자 피드백 — 달력일 진척률과 기술 게이트를 분리 (기존 지침보다 우선)
1. **당일 완료율**은 그 KST 날짜에 사용자와 약속하고 수행한 **완료 가능한 날짜별 작업 묶음**을 분모로 삼는다. 장기 외부 의존성·정식 NAS 진입 조건을 당일 작업으로 잘못 끼워 넣지 않는다. 미해결 의존성은 **다음 날 업무/기술 게이트**에 별도 상태로 유지하되 숨기거나 해결됐다고 하지 않는다.
2. 앞당겨 수행했더라도 실제 실행 날짜와 원래 예정일을 나란히 표시. 사후 분모 정정 시 **원본 기록·사유·기존 75%를 보존**한다. 이를 진행률 조작으로 이용하지 않으며, 이후 업무는 가중치/완료 기준을 시작 전에 선언한다.
3. 구체적 예: 10/24 실제 산출물 4건은 **100% 완료, 당일 잔여 0시간**; 원래 10/24 시간 계획 0시간/실제 소요 미측정, 조기 수행된 10/25 G1 공식 CLI/Agent 검증은 여전히 **BLOCKED**, 10/25 별도 계획 1.5h+예비 1.5h, 실제 완료 ETA는 미정.
4. **당일 완료율 100%는 전체 UGREEN 완성 100%가 아님.** 전체 프로젝트 퍼센트는 검증 가능한 범위·분모를 정하기 전까지 계산하지 않는다. 현재 SDK 호환성 미검증인 G2/G3b 코드도 공식 Skill 완제품으로 표시 금지.
