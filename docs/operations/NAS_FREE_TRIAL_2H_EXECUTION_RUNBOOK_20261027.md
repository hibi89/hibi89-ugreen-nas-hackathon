# UGREEN FlowPilot — 무료 NAS 체험 2시간 내 실증·수정 실행계획

**의사결정:** 2026-10-27, 사용자 직접 지시. **담당:** UGREEN lead/ugreen.
**상태:** 사전 준비 계획만 확정. 일반 무료 데모의 실제 발급·3시간 제공 여부·Uliya/Skill/Expert Agent 설치/호출 권한은 **별도 검증 전까지 UNVERIFIED**. 이 문서는 NAS 실행이나 제출 완료 증거가 아니다.

## 1. 목표와 시행 조건
- 사용자가 승인한 목표: **제품 코드/Skill/제출물과 오프라인 검증을 충분히 끝낸 뒤**, 일반 NAS 무료 체험이 실제로 쓸 만한 경우에만 **2시간 이내**로 핵심 FlowPilot 시나리오 검증 + 간단한 호환 수정 + 재검증을 마친다.
- 일반 체험 안내의 **3시간이 실제로 적용되는 계정일 때만** 120분 작업·60분 비상 예비로 설계한다. 체험 발급/유효시간/재발급/시계 시작 방식은 확인 전 확정하지 않는다. 공식 해커톤 본선 배정 NAS 24시간 권한과 **별도**로 취급한다.
- **2시간 완료는 운영 목표이지 보장/약속이 아니다.** 원격 Skill 설치나 공식 Expert Agent 권한이 없으면 2시간으로 고칠 수 없다. 이런 경우 즉시 **PLATFORM_UNAVAILABLE**로 판정하고 예선 자격·제출 작업은 오프라인으로 유지한다.
- 예선은 NAS 실기기가 없어도 되는 **별도 제출**: 2026-11-16 16:45 KST까지 공식 원본 요건에 맞는 Markdown-only SKILL ZIP + 영문 10문항/500단어 이하 PDF + 승인/접수증이 우선. 체험 대기로 제출 지연 금지.
- 본선 진출 시 주최 측이 따로 제공하는 정식 NAS 테스트 기회는 독립 게이트다. 일반 데모 성공이 본선 권한·성능을 증명하지 않는다.

## 2. 체험 활성화 **이전** 반드시 끝낼 일
- [ ] FlowPilot 최초 설계와 현행 기능의 갭 매트릭스를 작성/갱신: 사용자 자연어 → 의도/필수 입력 질의 → 권한 범위 → 단계별 계획 → 등록 Agent 위임 → 실증 근거 보고. **작동/합성만/계획뿐** 각각 분리 기록. 초기 4개 허용 시나리오(HANDOFF_AUDIT, CHECK_REQUIRED, REVIEW_VERSIONS, SUMMARIZE_SELECTED)와 범용 n8n형 미래 비전은 혼동 금지.
- [ ] 실제 저장소 HEAD에서 오프라인 테스트 전체 성공 증거 확보(발견 테스트 수와 종료 코드 포함). 기존 G43~G48 코드를 검증하고 0-tests PASS 방지. 실패·SKIP은 명시. 본선에서 사용할 새 Skill은 공식 Creator 사용/Checker를 **해당 최종 SHA**로 증빙해야 하며, 과거 ProjectReady G36/G37 통과를 새 FlowPilot 통과로 대체하지 않는다.
- [ ] 원본 SKILL.md, 허용 Markdown references, 영문 10문항 PDF, 검사용 ZIP을 **같은 revision**으로 확정하고 SHA256·크기·검사 결과 기록. 배포 ZIP에 개발용 Python/JS, 비허가 바이너리, 비밀/고객 자료를 넣지 않는다. 자료/라이선스/AI 이용 표시와 사용자 최종 승인 별도.
- [ ] 명령 이름·인자·응답 구조는 **공식 확인된 도구만** 사용. 지원/권한 미확인은 명령을 지어내지 말고 테스트 항목을 NOT_AVAILABLE로 표시. read-only delegation/approval/complete pagination/symlink policy를 점검. 확인 전 Cloud/Local 처리 경로를 단정하지 않는다.
- [ ] 시험용 **비민감 합성 폴더** 1개와 명확한 상대경로 파일 목록/버전 충돌·필수 파일 누락·접근 거부/불완전 목록 등 5개 테스트 케이스 준비. 실고객 데이터·비밀번호·토큰·다른 계정 폴더 금지.
- [ ] 환경별 변경점을 1곳에서 고칠 수 있도록 **문서화한 adapter/capability 표와 실패 유형→최소 수정 위치→재검사 순서**를 준비. 실제 Uliya API 존재를 가정하는 하드코딩/포크는 금지.
- [ ] 체험 계정 이용약관·시간제한·Uliya/Skill/등록 Expert Agent의 테스트 이용 허용 여부를 확인한다. **예상만으로 무료 시간을 활성화하지 않는다.** 실제 권한이 없다면 제품 수정이 아니라 접근 불가로 분류.
- [ ] Owner가 체험 시작 시점과 화면 조작을 승인한다. 관리자 기능/개인정보 업로드/설정 변경/외부 서비스 연동은 별도 명시 승인이 필요하다.

## 3. 3시간 체험 가정 시 **2시간 실행 타임박스** (T=실제 최초 이용 가능 시점)
| 구간 | 목표 | 완료/중단 판정 |
|---|---|---|
| **T+00~15분** | 로그인 및 사용권·남은 시간 확인 → Uliya/Skill/공식 등록 file-agent, document-agent, 권한·지원 명령을 읽기 전용으로 확인 | 필수 기능/권한이 없다면 **즉시 중단**. 일반 UGOS 화면만 작동하면 NAS 실행 PASS 아님 |
| **T+15~35분** | 합성 허용 폴더만 열어 실제 파일 목록/메타데이터, 경로 제한, 페이징/응답 필드와 Skill 위임 계약 확인 | 최소 1회 근거 있는 read-only 호출 성공 또는 실패 유형·증빙 보존 |
| **T+35~75분** | 승인된 Skill로 최소 3개 시나리오: 정상 필수 파일, 누락/불완전 조회, 버전 충돌·선택 문서(권한 있을 때만). 실제 source/ref와 결과 비교 | 등록 Agent 호출·결과 출처·동작/미지원/불확실 각각 표시, 합성 결과를 NAS 실증으로 승격 금지 |
| **T+75~105분** | 실제 발견한 **작은 계약·파라미터·응답 파싱 차이만** 최소 수정. 수정 전 원본 백업·SHA 확보, 건당 15분 이상 지체 시 해당 문제 후순위 | 구조 재설계·다중 기능 추가 금지. 공식 권한 부재/라이선스 문제는 소스 수정으로 우회 금지 |
| **T+105~120분** | 수정 버전 1회 재실행, 성공/실패 증거·현재 SHA·로그 정리, 남은 항목/심사 제출 영향 명시 | 완료 시 결과 보고. **2시간 종료** 후 60분은 긴급한 동일 버그 재시도에만 보존 |

**60분 예비:** 처음부터 전부 소비하지 않는다. 로그인 세션 종료 시 남은 시간이 사용 가능한지 확인 전제; 타이머 일시정지·재사용 보장 없음. 예비를 쓸 경우 원인·승인·남은 시간부터 기록.

## 4. 실패 분류와 빠른 의사결정
| 분류 | 즉시 대응 | 절대 하지 않을 일 |
|---|---|---|
| ACCOUNT_OR_TIME_UNAVAILABLE | 계정/세션/시한 기록, 체험 취소·중단; 공식 해커톤 환경 대기 | 무한 재신청, 제한 우회, 재생성 보장 주장 |
| ULIYA_OR_AGENT_NOT_AVAILABLE | 15분 내 BLOCKED/NOT_CHECKED, 기본 UGOS UI만 정보 수집 후 종료 | 가짜 성공 로그, 다른 앱으로 공식 NAS Skill 실행을 대체 |
| PERMISSION_OR_DATA_SCOPE_DENIED | 정확한 허용 폴더/동의만 재확인, 미승인 접근 중지 | 경로 우회, 타 사용자 파일, 임의 삭제·복사·외부 전송 |
| ADAPTER_ARGUMENT_OR_RESPONSE_MISMATCH | 확인된 SDK/Agent 계약에만 최소 매핑 패치, 합성 1회→NAS 1회 재실행 | 확인 없는 임의 CLI 호출, 공식 등록 Agent 우회 |
| SKILL_VALIDATION_OR_RIGHTS_HOLD | 변경된 후보의 공식 Checker/Creator 결과·라이선스 기록; 출시와 제출을 분리 | 미검증 버전을 PASS로 제출, 원본·해시 소급 수정 |
| FUNCTIONAL_FAILURE | 재현 가능한 1개 핵심 경로 우선, 15분 초과 수정은 보류하고 실패 근거 기록 | 범위 확대/전체 엔진 재구축 |

## 5. 증거·인수인계 기준
- 기록 필드: **체험 종류/실제 기기·OS 버전(보이면)/시작·종료 KST/남은 시간/Skill Git SHA+파일 SHA/허용 시나리오/공식 Agent 이름·검증된 호출·권한/실제 파일 근거(비민감)/성공·실패·미실행/수정 커밋/다음 조치**.
- 증거는 필요한 최소의 **비민감/합성 정보만** 남긴다. 계정 화면·토큰·실제 폴더명·개인 파일 원문을 Public GitHub에 올리지 않는다. 실증 동작은 각 단계마다 **REAL_NAS_PASS / REAL_NAS_FAIL / BLOCKED / OFFLINE_ONLY / NOT_RUN** 중 하나로 표기한다.
- 새로운 발견으로 Skill이나 제출 PDF/ZIP이 바뀌면 검증·해시·승인 절차를 다시 밟는다. 원본 ProjectReady와 과거 제출 후보를 덮어쓰지 않는다.
- 완성으로 인정할 조건: **검증된 등록 Expert Agent로 최소 1개 허가된 read-only 파일 시나리오를 실제 실행**, 출처와 결과를 증빙하고 핵심 실패 경로를 재현 가능한 방식으로 보고. 복잡한 n8n형 오케스트레이션 기능까지 완료됐다고 주장하지 않는다.
- 실행 담당자는 체험 사용 이전에 이 문서를 체크리스트로 다시 점검하고, 결과를 `docs/roles/lead/LEAD_ACTIVE_WORK.md`·`HANDOFF.md`에 인계한다. 별도 승인 없는 체험 시작·유료 결제·배포·Devpost 제출 **금지**.
